# SSH.NET S01 embedded transport evaluation

Date: 2026-09-14. Status: accepted on the supplied Windows 7 SP1 x64 machine
against the controlled Debian 12 server. Corrected package 0.6 passes its
offline self-test and both public-key-only and optional-password network runs.

## Decision boundary

S00 accepted Microsoft Win32-OpenSSH 10.0p2 for non-PTY command transport but
rejected its redirected process path for an interactive VT7 terminal because
the target PTY remained 0 by 0 and the exact Windows source obtains geometry
through console handles and input events. S01 evaluates an embedded backend
that exposes the missing channel controls directly.

The candidate is SSH.NET 2026.0.0, source tag `2026.0.0`, commit
`7b2fd3dbf2c86a80a7b06cea020aa5f821c9902e`. The probe targets .NET Framework
4.8 x64 and consumes SSH.NET's net462 assembly. It remains separate from
`VT7.sln` and the application project. The accepted result selects the
production candidate; this diagnostic does not perform that integration.

## Probe design

The package runner verifies every staged file before starting. Its optional
`--self-test` mode makes no network connection and checks:

1. all twelve runtime DLLs are present, inspectable and hashed;
2. the loaded SSH.NET assembly is exactly `2026.0.0.1` with informational
   version prefix `2026.0.0`;
3. the algorithm inventory contains `sntrup761x25519-sha512`, `ssh-ed25519` and
   `chacha20-poly1305@openssh.com`;
4. an encrypted OpenSSH Ed25519 fixture rejects a wrong passphrase and loads
   with its documented non-secret fixture passphrase; and
5. fingerprint comparison and error serialization do not retain injected
   endpoint or key-path text.

The fixture private key is test data. No server may authorize its public half.
It exists only to make encrypted-key parsing a repeatable Windows 7 load check.

Network mode reads the endpoint, port, username, private-key path, optional
private-key passphrase, trusted SHA256 fingerprint and optional account password
inside the probe process. Passwords and passphrases are masked. None of these
values is placed on a child-process command line or written to evidence. The
manifest retains only platform identity, component hashes, redacted exception
classes, protocol names, byte counts/hashes and pass/fail observations.

The controlled-server sequence covers:

| Case | Required observation |
| --- | --- |
| `host-key-rejection` | One host-key event refuses a forced changed-key decision before authentication. |
| `public-key-connect` | Out-of-band SHA256 trust and the dedicated key authenticate; hybrid post-quantum KEX, Ed25519 and modern AEAD or AES-CTR/HMAC-SHA2 transport protection are selected. |
| `command-byte-fidelity` | Binary stdout and stderr, including NUL, ESC, UTF-8 and invalid UTF-8, are exact and exit status 37 propagates. |
| `interactive-pty` | `xterm-256color` starts at 80 by 24; an exact raw frame survives; live 100 by 30 and burst-final 93 by 31 sizes reach `stty`; 131071 bytes drain; shell exit yields EOF. |
| `active-command-cancellation` | An actively writing Python command produces bytes and terminates within the bounded cancellation interval. |
| `session-isolation` | Two independently authenticated clients run overlapping token streams with no cross-session output. Only hashes and lengths are retained. |
| `active-disconnect` | A genuinely idle pending read completes at EOF after the session owner disposes the shell stream, then the client disconnects and remains disconnected. |
| `password-authentication` | If requested, keyboard-interactive and password methods share one controlled secret owner; prompts are counted but prompt text and responses are not retained. |

The server prerequisite is the owner's controlled Debian 12 host with bash,
`/usr/bin/python3`, `sh` and `stty`, using the unprivileged `sshtest` account.
The Ed25519 host fingerprint must come through a separate trusted administrative
path.

## Supplied Windows 7 result from package 0.5

The owner returned the complete sanitized `Logs` directory from Windows 7 SP1
x64. The offline run passed all four cases. Two network runs followed against
OpenSSH 9.2p1 on Debian 12: one requested the optional password case and one did
not. Their manifests contain no endpoint, username, fingerprint, key path,
password or passphrase.

Both network runs prove the candidate transport features:

- forced host-key rejection passed, while the accepted path saw exactly one
  trusted Ed25519 host key and authenticated the dedicated public key;
- negotiation selected `sntrup761x25519-sha512`, `ssh-ed25519`, `aes128-ctr`,
  `hmac-sha2-256` and no compression in both directions;
- exact binary stdout/stderr and exit status 37 passed;
- the PTY passed initial 80 by 24 geometry, live 100 by 30 resize, burst-final
  93 by 31 resize, raw NUL/ESC/UTF-8 fidelity, a 131071-byte drain and EOF;
- active command cancellation completed in about 406 ms after receiving output;
- two simultaneous authenticated sessions passed without cross-session routing;
- the requested password run authenticated without a keyboard-interactive
  prompt, proving the password method path.

The overall result was false only because two probe assertions were defective.
`public-key-connect` required ChaCha20-Poly1305 even though SSH.NET 2026.0.0's
[exact `ConnectionInfo` source](https://github.com/sshnet/SSH.NET/blob/2026.0.0/src/Renci.SshNet/ConnectionInfo.cs)
places AES-CTR first in its default ordered cipher list; the observed AES-CTR
plus HMAC-SHA2 suite satisfies the intended modern protection boundary. The old
`active-disconnect` case continuously produced data, so its supposedly pending
read completed with 70 or 98 buffered bytes. It then waited for an EOF that a
locally initiated `SshClient.Disconnect()` does not by itself deliver to that
stream. Exact upstream [`ShellStream`](https://github.com/sshnet/SSH.NET/blob/2026.0.0/src/Renci.SshNet/ShellStream.cs)
and [`Session`](https://github.com/sshnet/SSH.NET/blob/2026.0.0/src/Renci.SshNet/Session.cs)
source shows that stream disposal wakes blocked readers and that the local
disconnect path does not raise the remote-disconnect event used to dispose the
stream. VT7 must therefore dispose its owned shell stream before disconnecting
the client.

Package 0.6 accepts AEAD or AES-CTR with HMAC-SHA2 under the same exact hybrid
KEX and Ed25519 requirements. Its shutdown case disables echo, waits for a
server marker, proves the next read remains pending while the remote process is
idle, disposes the stream, requires that read to return zero within five
seconds, and then disconnects the client. This tests the production ownership
order directly.

dependency closure.

## Retained reproduction procedure

1. Copy the exact 0.6 ZIP to Windows 7 and verify its SHA256.
2. Extract it into a fresh writable directory, preferably with spaces in its
   path.
3. Run `RUN-SSHNET-S01.cmd --self-test`. Return its `Logs` directory if it does
   not pass.
4. Run `RUN-SSHNET-S01.cmd`. Supply the controlled Debian values only at its
   prompts. Select the optional password case if that account still permits
   password or keyboard-interactive authentication.
5. Return the package's complete `Logs` directory. Do not include the private
   key or any separately recorded credential/fingerprint material.

S01 accepts SSH.NET 2026.0.0 as VT7's embedded interactive remote candidate on
the tested Windows 7 configuration. Load, strict trust, public-key and password
authentication, modern negotiation, command bytes and status, PTY bytes,
initial/live/burst geometry, drain, EOF, cancellation, owned shutdown and
session isolation all pass. This selects the backend and fixes its stream-first
teardown contract; production session identity and TerminalCore wiring remain
separate 3A/3B implementation work.
