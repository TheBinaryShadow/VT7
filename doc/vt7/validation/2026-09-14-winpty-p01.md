## Decision boundary

VT7's terminal core. It does not add an interactive shell to the WPF host. The
completed evidence supports the bounded backend selection recorded below.

## Implemented measurement

`VT7.WinPtyFixture.exe` runs inside the hidden console created by WinPTY. It
records the visible `CHAR_INFO` cells, legacy attributes, cursor and dimensions
without sending that report through the terminal channel.

`VT7.WinPtyProbe.exe` connects WinPTY's named input/output pipes before spawn,
uses auto-shutdown and exit-after-shutdown, drains output through overlapped I/O
with a 30-second bound, and waits for both EOF and child exit. Every read is fed
through the same `VT7::Utf8TerminalStream` incremental decoder used behind ABI 9
and into an 80 by 24 TerminalCore with 1,000 history rows. Resize changes both
WinPTY and TerminalCore to 100 by 30 before releasing the child fixture.

The runner retains these views per case:

- `child.json`: exact console cells, attributes, API result, requested/actual
  code page, availability/set result and mode;
- `backend.bin` and `backend-visible.txt`: exact reconstructed bytes and an
  escaped human-readable view;
- `probe.json`: child/agent lifecycle, decoder state and final TerminalCore
  text, cursor, size, RGB colors and legacy attributes;
- `comparison.json`: normalized side-by-side result; and
- a run-level `manifest.json` with machine, PowerShell and dependency identity.

Lead/trail console cells are normalized only for the semantic text comparison.
The exact duplicated cells and their `COMMON_LVB` flags remain in `child.json`.
Fidelity differences are reported, not treated as collection failures. Invalid
UTF-8, incomplete EOF, dependency drift, a child failure, a timeout or missing
evidence does fail the run.

Build the Release package on the development machine:

```powershell

```

On the Windows 7 x64 target, extract the ZIP and run
`RUN-WINPTY-P01.cmd`. Return the complete timestamped `Logs` folder. The target

all comparison outcomes. In particular, the Windows 10 processed-VT result must

The first issued package, `VT7-WinPTY-P01-0.1-x64.zip`, reached Windows
PowerShell 5.1 on the Windows 7 target but stopped before creating `Logs`.
The batch file passed its `%~dp0` directory with a trailing backslash inside
quotes. Native argument parsing preserved the closing quote in
`BinaryDirectory`, so `[IO.Path]::GetFullPath` rejected the value as containing
an illegal character. This is launcher evidence only; no probe process ran and
no backend result can be inferred from it.

Package 0.2 changed the directory argument to `%~dp0.`, which preserves the
same resolved directory without a quote-adjacent trailing backslash. Probe,
fixture, WinPTY, test script and readme bytes are unchanged from package 0.1.
The shipped 0.2 ZIP was extracted into a directory containing spaces and its
actual `RUN-WINPTY-P01.cmd` was run through `cmd.exe` and Windows PowerShell
5.1.19041.7725. All eighteen cases completed and the launcher returned zero.

The supplied Windows 7 package 0.2 run completed five cases, then stopped at
`write-console-a-932`. `SetConsoleOutputCP(932)` returned zero with
`ERROR_INVALID_PARAMETER` (87); the fixture returned 2, and the probe correctly
retained 86 bytes containing that failure. The completed W, buffer, CP437,
CP850 and CP852 cases all have valid UTF-8, equal dimensions, text and legacy
attributes. The W case retains the already known cursor-width difference. The
initial target console output code page is 852. This partial result contains 33

`artifacts/vt7/evidence/winpty-p01-win7-0.2/winpty-p01-20260914-055453/`;
`ARCHIVE-VERIFICATION.json` inventories every retained byte.

Code-page selection is a target capability, so aborting here was a harness
assumption rather than a WinPTY failure. Payload 0.2 now records the requested

error and the actual output code page. If selection fails, it sends no bytes
under the wrong mapping, captures the unchanged console, and continues. Run
directories also include a random suffix to prevent rapid invocations from
sharing evidence paths.

`StringComparison.Ordinal`; focused modern-OS checks confirm that unprocessed
raw VT remains different while processed VT is equal where Windows accepts mode
bit `0x4`. A future package would use identity 0.4; no Windows 7 rerun is needed.

## Backend decision

Select the pinned WinPTY 0.4.3 native library and agent as VT7's Windows 7
local backend for legacy console applications, behind the replaceable session
boundary. P01 is complete. This decision includes these product constraints:

- describe the backend as legacy-console screen reconstruction, not transparent
  transport of arbitrary original VT sequences;
- expose or log requested versus actual code-page failures and never send bytes
  under a mapping the console rejected;
- accept that supplementary-plane characters can disagree with the child
  console cursor width even when the visible text matches;
- retain final-state correctness while recognizing that rapid overwritten
  intermediate states are not observable; and
- keep direct SSH bytes outside WinPTY so remote VT capabilities are not reduced
  to the Windows 7 console model.

Production session ownership, interactive input, Ctrl+C, mouse, shutdown races,
and repeated open/close remain 3A/3B implementation work. Those are integration
requirements, not reasons to reopen P01.
