# H01 typed-command shim and barrier diagnostic

Date: 2026-09-19

Status: accepted on Windows 7 in VT7 0.7.3/native ABI 11. Packages 0.1 through
0.3 passed every embedded shell/barrier case while exposing the successive
downlevel console-handle restrictions in external fallback. Package 0.4 uses
the documented Windows 7 standard-handle inheritance behavior and passes the
strict three-shell target run. Embedded SSH remains disabled and no network
endpoint was used.

## Boundary

H01 proves the command-resolution and ordering boundary required before the
accepted SSH.NET S01 transport can be integrated into a live local session. It
does not implement `SshNetTransport`, trust or authentication UI, real network
startup, or the final typed-SSH product path.

The diagnostic adds a VT7-authored native x64 console shim built for the Windows
7 subsystem. A private `shim` directory is prepended only to each diagnostic
WinPTY environment. The parent, user and machine environments are unchanged.
The identical binary is exposed as `ssh.exe` and the explicit `ssh-system.exe`
bypass name.

## Implemented contract

The native shim and managed broker implement:

- an unpredictable per-session 128-bit local pipe name and 256-bit capability;
- a first-instance, overlapped byte pipe with `PIPE_REJECT_REMOTE_CLIENTS` and
  an explicit DACL for the current logon SID and LocalSystem;
- protocol version 1, 64-KiB frames, bounded argument/string counts, fresh
  client/server nonces and HMAC-SHA256 authentication;
- named-pipe client PID, process creation-time, root ancestry and WinPTY console
  membership validation while the process handles remain open;
- console-standard-handle validation and exact fallback for redirection or
  unsupported grammar;
- interactive `-4`, `-6`, `-l`, `-p`, `-i` and one literal destination only;
- exact absolute fallback executable identity and SHA-256 revalidation;
- Windows CRT-compatible command-line quoting, selected-handle inheritance,
  exact external exit propagation and removal of `VT7_SSH_*` plus the shim PATH
  element from the fallback environment;
- one pre-acceptance fallback after pipe/authentication failure and no fallback
  after embedded acceptance;
- a unique visible barrier written by the shim through the ordinary console,
  acknowledged over the authenticated pipe, recognized only after its WinPTY
  bytes commit through `SessionOutputPump`, then completed by the host.

The test resizes WinPTY while the barrier is pending and requires preceding
shell output, the complete barrier and resumed shell output in that order.
PowerShell tests also prove function precedence and Croatian HR Latin terminal
input before invoking the ordinary `ssh` command.

## Rejected Windows 7 package 0.1

Two Windows 7 runs have the same result. Grammar, Command Prompt, Windows
PowerShell 5.1 and exact PowerShell 7.2.24 embedded/barrier checks pass. The run
then times out waiting for the external fallback fixture. This proves the pipe,
authentication, process/console association, Croatian input and barrier on all
required shells while isolating the failure to fallback process creation.

Package 0.1 duplicated the inherited console handles inside the shim and placed
those duplicates in `PROC_THREAD_ATTRIBUTE_HANDLE_LIST`. Windows console handles
may be duplicated only for the duplicating process; a child must receive console
access during process creation. Version 0.7.1 instead tried to mark the original
three standard handles inheritable. Package 0.2's added diagnostic output proves
that WinPTY's Windows 7 console handles reject `SetHandleInformation` with
`ERROR_INVALID_PARAMETER` (87) before `CreateProcess`.

The four returned files and per-file SHA-256 metadata are archived under
`artifacts/vt7/evidence/h01-win7-0.1-rejected`.

## Rejected Windows 7 package 0.2

Two package 0.2 runs again pass grammar and all three embedded/barrier paths.
Both then retain this exact fallback error in the WinPTY stream:

```text
VT7 SSH shim failed: SetHandleInformation failed for fallback (Win32 87)
```

Version 0.7.2 attempted to handle console and redirected standard handles
separately. For a console handle it opened `CONIN$` or `CONOUT$` with inheritable
security attributes; for a redirected file or pipe it created an inheritable
duplicate. Those three prepared handles entered
`PROC_THREAD_ATTRIBUTE_HANDLE_LIST`. Package 0.3 proved that this Windows 8-style
launch contract still is not valid for traditional Windows 7 console handles.

## Rejected Windows 7 package 0.3

The returned package 0.3 run again passes grammar, Command Prompt, Windows
PowerShell 5.1 and exact PowerShell 7.2.24 embedded/barrier checks. External
fallback reaches process creation and reports:

```text
VT7 SSH shim failed: CreateProcessW external SSH failed (Win32 1450)
```

Windows 7 uses traditional console handles. Microsoft documents that standard
handles are inherited on Windows 7 even when `bInheritHandles` is `FALSE`.
WinPTY author Ryan Prichard's public-domain Windows console research further
documents that `SetHandleInformation` fails for these handles and that placing
them in `PROC_THREAD_ATTRIBUTE_HANDLE_LIST` can produce erratic pre-Windows-8
behavior. The three target failures therefore identify one cross-version launch
boundary rather than a wider resource or H01 broker failure.

Version 0.7.3 queries the actual OS version through `RtlGetVersion`. On Windows
7 it uses `STARTUPINFO`, the original standard handles, `bInheritHandles=FALSE`
and no extended handle list. On Windows 8 or later it retains the explicit
`PROC_THREAD_ATTRIBUTE_HANDLE_LIST` path, including duplicated inheritable
redirected handles. This avoids broad inheritable-handle exposure on modern
systems while using the native console contract on Windows 7.

The returned package 0.3 files and per-file SHA-256 metadata are archived under
`artifacts/vt7/evidence/h01-win7-0.3-rejected`.

Rejected package identity: `VT7-H01-0.3-x64.zip`, SHA256
`4EBED0D43DC516E7B5211467F941EB419B134CA8F924C4013E30853AD2BEC79C`,
11,915,112 bytes, 35 verified files, application 0.7.2 x64.

References used for the correction:

- [Microsoft `CreateProcessW` documentation](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw), including the Windows 7 standard-handle inheritance note;
- [Ryan Prichard's Windows console documentation](https://github.com/rprichard/win32-console-docs#proc_thread_attribute_handle_list), which records the traditional-handle behavior around `SetHandleInformation` and `PROC_THREAD_ATTRIBUTE_HANDLE_LIST`. This CC0 research informed the OS split; no source code was copied into VT7.

## Reproduction procedure

1. Extract the archive into a new writable directory.
2. Run `RUN-H01.cmd` without elevation.
3. Return the complete `Logs` directory, whether the run passes or fails.

The strict runner requires the already documented Windows PowerShell 5.1 and
PowerShell 7.2.24 installations. It makes no network connection, does not use
the Debian server, does not read SSH keys and does not invoke installed OpenSSH.

## Acceptance boundary

H01 is closed for its bounded typed-command, exact-fallback and committed-output
barrier scope. This acceptance does not enable embedded SSH. Production SSH.NET
integration, direct SSH profile lifecycle, trust and authentication UI, real
server tests, overlay normalization and enabling the typed-shim allowlist remain
Milestone 5 work.
