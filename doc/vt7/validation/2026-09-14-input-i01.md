# I01 Windows 7 input-boundary characterization

Status: complete for the Windows 7 Croatian HR Latin 3A decision. Broader
layout, printable-repeat and IME acceptance remains in 3C.

## Question and boundary

I01 determines how the Windows 7 Croatian HR Latin layout reaches the two input
surfaces relevant to VT7: a WPF control and a child Win32 HWND hosted by
`HwndHost`. It also tests the inherited `TerminalInput` encoder with committed
text, Ctrl+C, cursor mode, focus mode, repeat suppression and actual AltGr
mappings. This characterization preceded the serialized outbound session queue.
The accepted 0.3.7/ABI 10 slice now implements its selected native-HWND adapter
and bounded ordering contract; it is not yet a live process-backend input path.

The inherited helper calls `ToUnicodeEx` with flags `0b101`. Microsoft documents
bit 2, which prevents keyboard-state changes, only for Windows 10 version 1607
and newer. The function otherwise changes the kernel keyboard buffer, including
dead-key state, and `TranslateMessage` changes that state too. Windows 7 behavior
therefore cannot be inferred from a Windows 10 pass. See the Microsoft
[`ToUnicodeEx` reference](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-tounicodeex).

The focus half deliberately hosts a native Unicode EDIT control inside WPF.
Microsoft documents that keyboard input goes directly to Win32 while an
`HwndHost` has keyboard focus, so WPF and native input must be observed
separately. See [WPF and Win32 interoperation](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/advanced/wpf-and-win32-interoperation).
The native recorder retains `WM_KEYDOWN`, `WM_KEYUP`, `WM_CHAR`,
`WM_DEADCHAR`, focus and size events. `WM_CHAR` is the UTF-16 character message
produced for the focused Unicode window after `TranslateMessage`; it is not
assumed to have a one-to-one relationship with key presses. See the Microsoft
[`WM_CHAR` reference](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-char)
and [keyboard-input overview](https://learn.microsoft.com/en-us/windows/win32/inputdev/about-keyboard-input).

## Diagnostic design

`VT7.InputProbe.exe` loads KLID `0000041A` without activating it system-wide. It:

- enumerates no-modifier, Shift and AltGr translations with `ToUnicodeEx`;
- finds a real layout dead key;
- compares flags 1 and 5 on independent worker threads so the two cases cannot
  contaminate each other's keyboard state;
- runs the inherited `TerminalInput` encoder with the Croatian layout selected
  through its existing test hook; and
- writes `native-probe.json` using schema `vt7-i01-native-v1`.

`VT7.InputFocusProbe.exe` is a .NET Framework 4.8 x64 WPF program. Its guided
seven-step sequence records Croatian lower/upper-case text, AltGr characters,
dead-key composition, repeat, Ctrl+C, Ctrl+Break, WPF/native focus changes and
native `WM_SIZE` ordering. It writes privacy-sensitive controlled field content
to `input-events.jsonl` and summary schema `vt7-i01-focus-v1`; the UI warns the
tester not to type passwords or private terminal content. It performs no global
input injection, starts no shell and uses no network.

`Test-VT7Input.ps1` validates both results and writes schema
`vt7-i01-run-v1`. The normal target path is interactive. `-NonInteractive` is
only a local lifecycle, output and launcher smoke test. `RUN-INPUT-I01.cmd`
uses 64-bit Windows PowerShell and a path form that tolerates spaces and a
trailing package directory separator.

Windows 7 treats flags 1 and 5 identically in this test. The `ToUnicodeEx` bit
2 non-mutating guarantee is unavailable, matching its documented Windows 10
version floor. Clearing bit 2 would preserve the same state-changing behavior
and is not a correction.

The guided text shows composition, but no repeated native printable A keydown
was captured. Modifier repeat and release behavior is present, and the inherited
encoder's repeat-suppression case passes automatically. Printable repeat remains
an ordinary end-to-end 3C case; it does not affect the 3A ownership decision and
does not require repeating this package.

## Accepted input and resize contract

I01 selects the native child HWND as the sole terminal-focus input boundary.
Production follows these rules:

1. Use OS-generated committed UTF-16 from the child character/composition path
   for printable, AltGr and dead-key text. Do not translate those keydowns again
   with `ToUnicodeEx` on the live UI thread.
2. Preserve native keydown/up metadata for non-text keys and explicit control
   distinctions. The inherited TerminalCore encoder remains the terminal-mode
   encoder; any layout-helper use must run away from the UI message thread or
   through a tested Windows 7 compatibility shim so it cannot disturb live dead
   state.
3. Correlate a handled control keydown with its following character message.
   Ctrl+C and Ctrl+Break both produced U+0003 after different keydowns; sending
   both paths would duplicate ETX and discarding the key metadata would lose the
   Break distinction.
4. On terminal focus loss, reconcile or release tracked modifiers before another
   focus owner can consume the physical key-up. Send focus-reporting sequences
   once according to TerminalCore mode.
5. Coalesce resize from the native surface's authoritative cell grid. Update
   TerminalCore and the backend with the same generation-tagged grid; do not
   send both WPF dimension notifications and child `WM_SIZE` as separate PTY
   resizes.
6. Serialize committed text, encoded key actions, paste, terminal replies and
   resize/control operations through the session owner. Reject stale items by
   session generation after close or replacement.
